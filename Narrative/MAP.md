# Narrative

Turning the real record of a build into something people read.

```
Narrative/
└── the-watcher/   mine git, transcripts, logs and timestamps into a dated chronicle
```

## Route

| Need | Skill |
|---|---|
| A devlog, development diary, or making-of | `the-watcher` |
| A game jam writeup | `the-watcher` |
| A launch thread with personality | `the-watcher` |
| A postmortem that is a story, not a form | `the-watcher` |
| A blameless incident postmortem for the team | the `incident` playbook in [`Agentic`](../Agentic/MAP.md) |
| Video topics for the content pipeline | [`topic-miner`](../topic-miner/SKILL.md) at the root |
| A feature demo video | [`demo-video`](../demo-video/SKILL.md) at the root |

## What makes it work

`the-watcher` reads the actual record: git history, session transcripts, engine logs, timestamps. Then it stages the result as acts, where **every chapter is a real obstacle with its real number**, and it closes with what is honestly still unverified.

That last part is the whole reason it reads as true. A devlog that only tells you what worked reads as marketing, and a chronicle that admits what is still broken reads as a build log, which is what people actually want.

It needs no other skill to do its job. It is a reader, not a workflow.
